# Qwen3.6 FP16 runtime validation

This work preserves the user's requested full-model FP16 configuration. It is
not a performance acceptance report. Existing BF16 results cannot establish
FP16 throughput or correctness.

## Native reproduction

`/mnt/vdb/chengzhi/layerkv_fp16_20260907_native_01/native.engine_args.json`
records a LayerKV-disabled run of Qwen3.6-35B-A3B snapshot
`995ad96eacd98c81ed38be0c5b274b04031597b0`, H100 NVL GPU0, TP1, dtypefloat16,
Triton attention, requests2, input128, output4, rounds1. The model loads and
allocates FP16 KV, then fails at first prefill with:

```
AssertionError("Mismatched type for col0 between then block (<['256'], bf16>) and else block (<['256'], fp16>)")
```

The location is causal_conv1d_triton's `if load_init_state` branch. Default
convolution-state storage is BF16 while the explicit model runtime dtype is
FP16. The scheduler reports SIGQUIT after the child failure; terminal exit137
does not by itself imply OOM. No generation result is present for this run.

## Fix

`ModelRunnerKVCacheMixin._mamba_cache_params_for_runtime` derives Qwen GDN
convolution storage from the already explicit `--dtype`. It preserves configured
SSM accumulation precision and does not mutate checkpoint config. Both normal
and disaggregated hybrid request-pool allocation use the resolved parameters;
cache memory accounting uses them as well. Non-Qwen state configurations remain
unchanged. There is no per-forward cast, kernel modification or new environment
variable. Shape/layer selection remains unchanged.

The regression exercises real Qwen3.5 MoE text configuration (also used by this
Qwen3.6 checkpoint). With old dtype selection, FP16 asserts BF16!=FP16 while BF16
and non-Qwen preservation pass. With the fix, all3 tests pass. A first test setup
omitted `full_attention_interval=4` and failed before the tested behavior; that
fixture issue was corrected before recording the dtype regression. Tests must
run from the worktree's `python/` directory, because the reused environment's
editable package otherwise resolves to a different checkout. The model driver
already inserts its own worktree Python path.
